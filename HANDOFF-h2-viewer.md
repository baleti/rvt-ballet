## What exists
- `rvtballet/save.py`: savegate wiring (element-level verify, memoised + disk-persistent snapshot cache), error mapping, guards (destination, memory estimate, page layout, cloud placeholder, busy/conflict), backups/restore/recover, progress stages, limited-verification SAVE AS.
- `rvtballet/edit.py`: edit ops recorded per model and replayed on the loaded bytes (undo = pop). Backends: `wledit` (default: string edit by old text) and `rvtedit` (`RVTBALLET_EDIT_BACKEND=rvtedit`, edit-lab `rvtedit.Edit`): string edit by parameter NAME/ID, numeric edit (`set_num`, Double/Int by name/ID), `move`, `delete` (opt-in `RVTBALLET_ENABLE_DELETE=1`). Exact id->value pairing is our own code (rvtedit.set_num edits the wrong Int parameter: reported). Multi-partition files: ops grouped per partition, applied as sequential passes.
- `rvtballet/lightverify.py`: structure-only verification (SAVE AS only, `light_verify`+`confirm`, labelled "LIMITED verification") for models too large for the element dump.
- The element dump runs in a worker subprocess under a hard memory cap (`RVTBALLET_SNAPSHOT_MEM_GB`, default = remaining viewer budget, min 2 GB): a model that does not fit => `too_big` 507, nothing written. POSIX only (no cap on Windows).
- UI `web/save.js`: Save as / Save / Backups / Undo edit, result panel (warnings, changed elements on a verify failure, progress), offer of limited verification on `too_big`, inspector pencil on string parameters (needs the rvtedit backend).
- Safety defaults: overwrite OFF (`RVTBALLET_ALLOW_OVERWRITE=1` AND an open oracle gate; the real gate file does not exist and was never opened), overwrite refused when a partition's page layout would change (`RVTBALLET_ALLOW_LAYOUT_CHANGE=1`), SAVE AS never touches the source, only Revit 2024 and 2026 are writable.
