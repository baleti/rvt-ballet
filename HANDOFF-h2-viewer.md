## Layout guard vs the overwrite workflow (UPDATED with real-file data)
By default SAVE (overwrite) is refused when a partition stream's page layout would change (RVTBALLET_ALLOW_LAYOUT_CHANGE=1 overrides). On SYNTHETIC write-lab scenes the second edit of a writer-made file re-pages the stream (payload exactly at capacity, no slack), so a second overwrite in a chain would be refused. On a REAL 2024 project (7.6 MB, copy) three successive overwrite rounds all succeeded with verify clean, no layout warning, constant size (-20 KB vs the original: our deflate is tighter than Revit's, so the stream gains slack) and all earlier edits present. So the guard does not block repeated overwrites on the real file tried; its trigger looks like a synthetic-scene artefact. Re-paged synthetic files opened in Revit (2024 gen4/gen8, 2026 gen3 audit ON), so the guard has no Revit evidence of harm either way. Keep it (it costs nothing on real files) or relax it to a warning: orchestrator/user decision; sample = 1 real file.
