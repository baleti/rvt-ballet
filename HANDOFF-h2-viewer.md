## DECISION NEEDED: layout guard vs the overwrite workflow
By default SAVE (overwrite) is refused when a partition stream's page layout would change (RVTBALLET_ALLOW_LAYOUT_CHANGE=1 overrides). After the FIRST overwrite the file on disk is writer-made, so the NEXT edit is a second-generation edit and re-pages the stream => the second overwrite in a session chain is refused by default. That blocks the 'edit, save, edit, save' workflow the main goal needs. Evidence so far that re-paged files are harmless: opened in Revit: 2024 gen4, gen8 (audit off), 2026 gen3 (audit ON, SaveAs+reopen equal). Evidence against: none. Audit-ON passes now exist for a re-paged file on BOTH years (2026 gen3, 2024 gen8: 77 pages, cap_last 0, SaveAs+reopen equal), so the stated criterion is met on synthetic scenes; the remaining caution is that there is no real-project sample. The orchestrator/user should decide whether to turn the overwrite refusal into a warning (one-line change in save.save_overwrite) or keep it until a real-project sample passes. Until then the safe default stays.
